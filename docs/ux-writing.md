# UX writing for README and plans

Rules for README `TEST_PLAN.md` and short docs in this repo.

## Voice

- Plain facts only. No hype no roadmap poetry no “what this unlocks”.
- Curly apostrophes: write don’t it’s Milestone’s (’ U+2019) not straight '.
- No Oxford comma: “Swift Kotlin and the CLI” not “Swift, Kotlin, and the CLI”.
- Never use the word “alongside”.
- End every section and the document on a fact not a wrap-up or call to action.
- No AI wrap-ups (“In summary” “Overall” “Hopefully”).

## Structure

- Lead with what the thing is.
- State private vs public status when the audience could assume open source.
- Point to `TEST_PLAN.md` for gates; do not duplicate the full go/no-go table in the README.
- Prefer short tables for criteria ownership and layers.

## Words to avoid

- alongside
- unlock / blazing / seamless / delight
- “agents and humans alike”
- trailing cheer (“Let’s build”)
